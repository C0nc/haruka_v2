# Haruka v2 — spatial contrastive decomposition

Haruka separates what a condition changes in a tissue from what it shares with the control. Each cell gets a
background latent z (shared by control and condition cells) and a salient latent s (condition-specific), and the
decoder predicts both the cell's expression and its spatial neighbourhood, so s captures how the condition reshapes
local tissue context. This branch (`v2`) contains only the current default model and the code that reproduces every
paper figure from it.

## The model

The default model for every paper figure is the **composition-gated shared-decoder Haruka**
(`bench_kras_xenium/run_haruka_separate_batch_heads.py` → `bench_mouse_brain_scviva/run_haruka_shared_decoder.py`):
z (background, shared) and s (salient, zeroed by the decoder for control cells) feed an NB expression decoder plus two
niche heads (k = 20 neighbour cell-type composition, composition-gated neighbour mean expression, spatial weight 100);
one-way z←s ridge independence (λ = 10); batch injected into the decoders only. The salient composition shift
D([z,s]) − D([z,0]) is the per-cell counterfactual "what the condition changed in this neighbourhood".
z-vs-s readouts are always computed on condition-arm cells (control s is never used by the decoder).

## Setup

```bash
git clone -b v2 https://github.com/C0nc/haruka_v2 && cd haruka_v2
conda create -n haruka2 python=3.11 -y && conda activate haruka2
pip install -r requirements.txt
bash install_contrastivevi_patch.sh        # installs the model: patched scvi-tools ContrastiveVI module
python -m ipykernel install --user --name haruka2
```

## Reproducing the figures

| notebook | figure | dataset |
|---|---|---|
| `notebooks/00_default_model.ipynb` | — | model, default arguments, per-dataset keys |
| `notebooks/02_fig2_benchmark.ipynb` | Fig. 2 | paired mouse-brain simulation, 5 sections, 4 baselines |
| `notebooks/03_fig3_ad_plaque.ipynb` | Fig. 3, ED Figs 3–4 | AD STARmap + human AD CODEX |
| `notebooks/04_exercise.ipynb` | exercise | aged mouse brain MERFISH, exercise vs control |
| `notebooks/05_petracer.ipynb` | PEtracer | lineage-traced lung tumours (M2-1) |
| `notebooks/06_fibrosis.ipynb` | fibrosis | GSE250346 lung fibrosis Xenium + H&E regions |
| `notebooks/07_kras.ipynb` | KRAS | KRAS-inhibitor mouse lung Xenium 5K |

Preprocessed inputs for every notebook (~3.7 GB, SHA-256 listed) are on Hugging Face: [C1vy/haruka_v2_data](https://huggingface.co/datasets/C1vy/haruka_v2_data); section 0 of each notebook downloads and links them (`RUN_DOWNLOAD=1`).
Each notebook runs every step as a shell command gated by stage (`download`, `data`, `fit`, `analysis`, `figure`).
By default a notebook runs end to end: its inputs are read from Hugging Face (section 0), then fit, analyses and figure
(hours on one GPU). `HARUKA_FIGURE_ONLY=1` redraws the figure from saved outputs; the `data` stage (off) rebuilds the
inputs from the raw public releases. `notebooks/run_all.sh` executes all of them. Notebooks are generated by
`notebooks/build_notebooks.py`; figure scripts live in `figures_paper/` (shared style `paperstyle.py`), and
`figures_paper/compose_svg_pages.py` assembles the whole-page vector SVGs.

Paths resolve from the clone location (`HARUKA_ROOT`); large fit outputs of the exercise and fibrosis steps go to
`HARUKA_WORK` (default `<repo>/work`). Data, fits and intermediates are not in git.

## Layout

| path | contents |
|---|---|
| `contrastivevi_patch/` | the model: patched `scvi/external/contrastivevi/` module (scvi-tools 1.4.0.post1) |
| `bench_mouse_brain_scviva/run_haruka_shared_decoder.py` | fitting entry point (niche targets, composition-gated decoder, z/s outputs) |
| `bench_kras_xenium/run_haruka_separate_batch_heads.py` | default wrapper: separate batch projectors for the two niche heads |
| `bench_*/` | per-dataset data preparation, fit launchers and analyses used by the notebooks |
| `figures_paper/` | panel scripts, page composers, source data and final figure pages |
| `notebooks/` | one reproduction notebook per figure + `repro.py` helpers |
